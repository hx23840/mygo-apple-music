# 测试记录与复现

## 离线检查

```sh
npm test
npm run test:native
bash scripts/build.sh --diagnostic
npm run smoke
bash scripts/package.sh
```

JS 测试覆盖桥接并发、超时与退出恢复、收藏和歌单持久化、编辑竞争、导入删除标记、存储失败、歌词匹配与限流。Swift 测试覆盖身份编码、路由、参数边界和 DTO。

`smoke` 启动实际辅助程序检查协议，不请求音乐授权或播放歌曲。诊断包不能用于播放。需要正常 macOS 桌面环境运行 LaunchServices 桥接检查。

CI 在 Linux 运行 JS 测试，在 macOS 运行 Swift 协议测试、完整诊断编译和打包。CI 不含 Apple 账号、开发签名或真实播放验证。

## 实际播放检查

先按 [构建指南](BUILDING.md) 生成已签名的辅助程序，再运行：

```sh
npm run verify:live
```

该命令会请求音乐访问权限并播放音频。它验证专辑、音乐人、搜索、封面、辅助程序重启后播放，以及跳转到 100 秒、暂停、恢复和切歌。检查结束停止辅助程序。

测试要求资料库中有专辑、有效音乐人关联、可读封面以及歌单中的可播放歌曲。它检查前 20 个专辑和前 10 个歌单，播放样本需要满足脚本中的时长要求。不满足测试数据前提会报错，不表示所有资料库内容都不可播放。

## 本地管理与歌词检查

选择资料库中一首在 LRCLIB 有同步歌词的歌曲。

```sh
export APPLE_MUSIC_TEST_TITLE='歌曲名'
export APPLE_MUSIC_TEST_ARTIST='音乐人名'
npm run verify:local
```

此检查调用真实音源及 LRCLIB，但把收藏和歌单编辑写入隔离的内存存储。它验证收藏、歌单导入编辑、重新加载和歌词匹配，不修改实际 MyGo 插件存储，也不写回 Apple Music。

## 已完成的实机验收

2026-11-07，0.3.0 在 Apple Silicon macOS、本机开发者签名及 MyGo v0.1.21 上通过完整真实播放脚本，包括资料库读取、专辑与音乐人详情、搜索、封面和播放控制。

MyGo 实际界面验证了本地收藏、歌单创建、添加曲目、重命名、排序，以及重启后的保留。同步歌词展示和点击跳转通过。0.3.1 随后通过隔离存储的真实音源与歌词检查。该版实际界面确认左下角仅显示原生设置入口、可打开设置窗口、专辑网格正常，并观察到播放进度推进；没有重跑完整真实播放脚本。

这些结果来自一台已授权设备，不代表跨设备签名、公证或所有资料库数据均已验证。未重置系统权限来重复首次授权弹窗。MyGo 自然结束后的自动切歌未在界面单独验收；原生结束信号和手动切歌已验证。Intel 目标没有实机验收。

独立 Apple Music REST 服务探针未取得 developer token。已通过的资料库和播放路径使用原生 MusicKit，不依赖该 REST 探针。签名成功不作为 App Service 注册成功的证明。

0.3.2 的开源整理主要调整签名配置、缓存目录选择和验证脚本输入。具体 CI 状态见仓库 Actions，真实音乐授权和播放不在 CI 覆盖范围内。

0.3.3 将插件入口、清单和翻译移至仓库根目录，保持运行逻辑不变。迁移后 30 项 JS 测试及原生协议测试通过；发行签名、公证和从 GitHub 安装需对最终 Release 附件另行验收。

## 0.3.3 发行包检查

2026-11-07，Apple Silicon 发行辅助程序通过 Developer ID Application 签名、Apple 公证和票据验证，Gatekeeper 返回 `Notarized Developer ID`。实际签名启用了 hardened runtime。

对同一公证产物重跑了完整真实播放脚本，资料库、专辑、音乐人、搜索、封面、辅助程序重启后播放、跳转到 100 秒、暂停恢复、切歌和结束信号均通过。发行签名首次音乐授权由用户确认。

随后通过 MyGo 原生“从 GitHub 安装”入口下载并安装 v0.3.3，设置页显示正确仓库来源和版本。安装后的 9 个包内文件与公开 ZIP 逐字节一致。专辑网格、详情和播放通过界面验收，进度持续推进后暂停。由本地包迁移到 GitHub 来源时，旧包通过 MyGo 移至废纸篓，本地收藏与歌单存储的指纹在迁移前后相同。
