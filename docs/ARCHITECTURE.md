# 音源适配架构

插件由 MyGo 加载的 JS 入口和本机 Swift 辅助程序组成。MyGo 提供全部浏览和播放界面，辅助程序使用 MusicKit 读取资料库、解析封面和播放受保护音频。

## 进程与授权

JS 通过 `host.spawn` 启动可执行文件的 `--bridge` 模式。该模式使用 LaunchServices 独立启动辅助应用，通过私有 Unix socket 转发 JSON Lines 请求。辅助应用包含 `NSAppleMusicUsageDescription`，音乐权限归属于辅助应用，不需要改动 MyGo 的 Info.plist。

临时目录权限为 0700，socket 权限为 0600，连接验证同用户。桥接结束后清理 socket。令牌和私钥不进入 JS 或 MyGo 插件存储。

插件不导出 `account`、`signIn` 或 `signOut`，MyGo 因此使用原生设置入口。读取和播放直接检查系统 MusicAuthorization。首次授权异步发起一次系统请求，同时向 MyGo 返回允许后重试的提示，避免阻塞宿主请求。原生账号协议仅保留给独立诊断脚本。

## 请求与响应

请求结构为 `{id, method, params}`。响应为 `{id, result}` 或 `{id, error: {code, message}}`。

JS 维护一个进程连接和一个 stdout 读取循环，以请求 ID 分发结果。待完成请求最多 32 个，超时为 25 秒。发生超时、协议错误或 EOF 时，拒绝全部待完成请求并结束连接。下次操作启动新进程，不自动重放播放命令。

## 歌曲身份和关联

歌曲 ID 使用 `am1:` 前缀及 Base64 编码数组。资料库歌曲保存 `library` 和原始歌曲 ID；歌单项保存 `playlist`、歌单 ID 和条目 ID。辅助程序重启后按原始引用恢复对象。

原生精确 ID 查询统一不同列表中的歌曲身份。音乐人关联使用原生分组结果，过滤空 ID 占位对象，不按名称猜测身份。专辑关联必须能由资料库查询解析才提供可点击 ID，否则保留名称和封面。

普通列表每页 100 项。完整歌单上限为 10,000 项，歌单列表上限为 5,000 项，超限返回错误。

## 播放和队列

MyGo 持有队列、随机和循环状态。JS 的 `remotePlay({ids, start, position})` 只向辅助程序发送选中的歌曲。

辅助程序使用 ApplicationMusicPlayer，每次建立一个包含当前歌曲的队列条目。状态返回 MyGo 原始 ID 和毫秒时间，不依赖 MusicKit 准备后可能变化的条目 ID。自然结束后由 MyGo 请求下一首，避免不可播放的其他条目阻止整单准备。

## 本地收藏和歌单

JS 通过 `host.storage` 保存版本化记录，包含收藏顺序、本地歌单、已导入标记和引用歌曲的元数据。它实现 MyGo 的收藏和歌单回调，源端不接收编辑操作。

Apple 歌单首先导入轻量条目，首次读取曲目时形成本地快照。删除保留导入标记，刷新不会重建副本。异步读取完成后基于最新本地状态提交，避免覆盖期间发生的重命名或恢复已删除歌单。写入失败不返回成功；损坏或未知版本的记录不自动重置。

## 封面和歌词

MusicKit 封面在原生进程内解析，缩放为 600 像素 JPEG，再通过 MyGo 支持的 file URL 提供。缓存按实际 Bundle ID 隔离，目录权限为 0700，文件为 0600，最多四个并行任务，上限 64 MB，期限七天。封面失败不阻止浏览。

歌词通过 LRCLIB 查询，验证歌曲名、音乐人、专辑与时长后返回 LRC。MyGo 负责解析和显示。请求包含超时、并发合并、限流冷却及本地缓存。没有同步歌词时返回空结果，不伪造时间轴。
